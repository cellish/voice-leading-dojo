## 1. 概要

**アプリ名**：和声道場 / Voice-Leading Dojo（旧名「数字付き低音ドリル」）

**目的**：数字付き低音のバスに上3声（S・A・T）を書き、和声の禁則をその場で確かめる。表記は林達也『新しい和声』に合わせている。

**主な機能**
- 例題6つ（`EXAMPLES`）と自作課題1つ（「課題を入力」）から課題を選ぶ
- 大譜表（自作の SVG）をクリックするか、キーボードで上3声を入力する（`svg` の click、`step()`、`setAcc()`、keydown）
- 入力のたびに17規則で判定し、エラー／注意の一覧を出す。一覧を押すと該当の音を囲んで示す（`check()`、`render()`）
- 規則ごとに「エラー／注意／オフ」を切り替える（`RULES` と設定パネル）
- 全体・1和音の再生と、平均律・純正律の聴き比べ（`playAll()`、`playOne()`、`compare()`）
- 表示の切り替え：音名のドイツ式表記、「＋4」「＋6」単独の読み方、自動送り、入力音の発音

**言語・ビルド・公開**
- HTML、CSS、素の JavaScript（ES2015 以降、IIFE の中に全部書く）。フレームワーク、ビルド、npm はどれも使っていない。
- 公開先は GitHub `cellish/voice-leading-dojo`（公開リポジトリ）。GitHub Pages 向けに `.nojekyll` を置いているが、Pages はまだ公開を確認できていない（`STATUS.md`・`PLAN.md`）。
- 同じアプリの古い版が claude.ai のアーティファクトとして別にある（このリポジトリの外）。

## 2. 音楽データの表し方（最重要）

### 音高
- **音名で持つ**：`{l, a, o}`。`l` は幹音（0〜6 が C〜B）、`a` は変化（-2〜+2）、`o` は科学的なオクターヴ番号（C4 が中央ハ）。
- **異名同音を区別する**。同じ音かどうかは `same(a,b)`（190〜199行）で判定し、`l` と `a` を比べる（オクターヴは見ない）。
- MIDI 番号は必要なときに計算する：`midi(n)=12*(o+1)+NAT[l]+a`。全音階上の位置は `dia(n)=o*7+l`。
- 文字列からの読み取りは `parseNote()`（255行）。`G2`、`C#3`、`Bb2`、`F##3`、`x` などを受け付ける。オクターヴは1桁だけ。
- 表示は `nName()`（244行）。英語式（`C♯4`）とドイツ式（`Cis4`、`B`、`H`）に切り替えられる。

### 音価・拍・小節
- **なし**。和音は「列」として等間隔に並ぶだけで、音価、拍子、小節線は持たない。符頭はすべて白い楕円で、符尾はない（`drawStaff()`）。
- 再生では全和音を同じ長さ（`st.tempo` 秒、既定は 1.4）で鳴らす。

### 声部
- 実施は `st.ans[k] = [S, A, T]`。和音ごとに長さ3の配列で、未入力は `null`。
- バスは課題側にあり（`st.ex.bass[k].note`）、判定のときに `notes(k)=[S,A,T,B]` として4声にまとめる（`check()` 内）。
- 声部の番号は 0=S、1=A、2=T、3=B。名前は `VN`、音域は `RANGE`（MIDI 番号の範囲、231行）。

### 和音
- **数字付き低音だけを持つ**。コードネームとローマ数字は持たない。
- `parseFig(fig, bass, key)`（281行）が、数字の文字列から構成音を求める。
  - 数字を省略形から完全な形に戻す：`ABBR`（例：`6` → `[6,3]`、`4/3` → `[6,4,3]`）
  - 完全な形から根音の位置と第7音の位置を引く：`SHAPE`
  - 記号は `+`（導音化）、`#`、`b`、`♮` を数字の前後どちらにでも付けられる
  - 「＋4」単独と「＋6」単独の読み替えは設定の `plus4`、`plus6` で決める
- 返り値：`{tones, root, third, fifth, seventh, known, sig}`。`known` が false（`SHAPE` にない形）のときは、構成音かどうかの判定だけをする。

### 調・転調
- 調は課題に1つだけ。`parseKey()`（269行）で読み、大文字は長調、小文字は短調。
- `makeKey()`（260行）の返り値：`{tl, ta, mode, tpc, sig, scale, lt, name}`。`sig` は幹音ごとの調号の変化。短調は**自然短音階**で持ち、導音 `lt` だけは主音の半音下として別に求める。
- **転調は扱わない**。一時的な臨時記号は数字の `#` や `+` で書けるが、導音の規則は常に主調の導音で判定する。

### データの例
```text
課題の文字列：  a  A2 C3:6 D3:6 E3:+ F3 D3:6 E3:7/+ A2
音：            {l:4, a:1, o:3}            // G#3
和音（E3:7/+）：{tones:[E,D,B,G#], root:E, third:G#, fifth:B, seventh:D, known:true}
判定結果：      {rule:'parallel', sev:'error', cells:[[2,0],[2,3],[3,0],[3,3]],
                 where:'第3→4和音', msg:'ソプラノとバスが連続8度です'}
```

**規則の一覧（`RULES` と `check()`）**

和音の中で見るもの：構成音以外の音（chordTone）、根音・第3音・第7音の欠落（missingTone）、第5音の省略（missingFifth、三和音だけ）、導音の重複（ltDouble）、音域（range、上3声だけ）、交差（crossing）、上声の間隔（spacing、S–A と A–T）。

2つの和音の間で見るもの：
- 連続5度・8度（parallel）と、反行による連続5度・8度（contrary）。どちらも全ての声部の組で見る。どちらかの声部が保留していれば対象外にする。
- 並達5度・8度（hidden）。外声（S–B）で、ソプラノが3半音以上動くときだけ。
- 声部の超越（overlap）。
- 導音の解決（ltOuter、ltInner）。根音が属音か導音の和音から、主音を含む和音へ進むとき。
- 第7音の2度下行（seventh）。
- 増2度・増4度の旋律（augMel）、7度とオクターヴを超える跳躍（leap）。
- 4声の同方向進行（sameDir）。

判定結果は `{rule, sev, cells:[[和音, 声部]…], where, msg}` の配列で、エラーが先に並ぶ。

**規則ごとの条件と既定の重さ**
| id | 既定 | 条件（`check()` の中） |
|---|---|---|
| chordTone | エラー | 上3声の音が `ch.tones` に、幹音と変化の両方で一致しない |
| missingTone | エラー | `known` の和音で、根音・第3音・第7音のどれかが4声にない |
| missingFifth | 注意 | 三和音で第5音がない |
| ltDouble | エラー | 主調の導音が2声以上にある（バスも数える） |
| range | 注意 | 上3声が `RANGE` の外（S 60–79、A 55–74、T 48–67） |
| crossing | エラー | 上の声部が下の声部より低い（S–A、A–T、T–B） |
| spacing | エラー | S–A または A–T が12半音を超える |
| parallel | エラー | 同じ組の声部が完全5度→完全5度、または8度・同度→8度・同度で同方向に進む |
| contrary | エラー | 上と同じ音程の組で、反行して進む |
| hidden | 注意 | S–B が完全音程でないところから完全音程へ同方向に進み、S が3半音以上動く |
| overlap | 注意 | 隣の声部が、前の和音の隣の声部の音を越える |
| ltOuter / ltInner | エラー / 注意 | 根音が属音か導音の和音で、次の和音が主音を含むとき、導音が半音上の主音へ進まない |
| seventh | エラー | 第7音が、次の和音（`sig` が違うとき）で全音階の2度下（1〜2半音下）へ進まない |
| augMel | エラー | 2度で3半音（増2度）、4度で6半音（増4度）の旋律進行 |
| leap | 注意 | 12半音を超える跳躍、または7度の跳躍 |
| sameDir | 注意 | 4声すべてが動き、しかも同じ方向へ進む |

**数字の省略形（`ABBR`）と、根音・第7音の位置（`SHAPE`）**
| 書き方 | 完全な形 | 根音（バスから） | 第7音 |
|---|---|---|---|
| なし、`5`、`3` | 5/3 | 1（バス） | なし |
| `6` | 6/3 | 6度上 | なし |
| `6/4` | 6/4 | 4度上 | なし |
| `7` | 7/5/3 | バス | 7度上 |
| `6/5` | 6/5/3 | 6度上 | 5度上 |
| `4/3` | 6/4/3 | 4度上 | 3度上 |
| `4/2`、`2` | 6/4/2 | 2度上 | バス |

この表にない組み合わせ（9の和音、増6の和音など）は `known:false` になり、構成音かどうかしか判定しない。

**保存データの例**（localStorage `harmony-figured-bass-drill-v1`）
```json
{"cfg":{"sev":{"parallel":"error","hidden":"warn"},"auto":true,"sound":true,
        "german":false,"plus4":true,"plus6":false},
 "answers":{"ex1":[[{"l":4,"a":0,"o":4},{"l":2,"a":0,"o":4},{"l":0,"a":0,"o":4}],[null,null,null]],
            "ex1init":true},
 "custom":"a  A2 C3:6 E3:+ A2","exId":"ex1","tuning":"et","tempo":1.4}
```
（`cfg.sev` は実際には17規則すべてを持つ。ここでは2つだけ示した。）

**入力の操作**
- 譜表をクリック：選んでいる声部（S／A／T）に、クリックした高さの音を入れる。変化記号は、その和音の構成音に同じ幹音があればそれに合わせ、なければ調号に合わせる（`smartAcc()`）。
- ▲▼ と ↑↓ キー：全音階で1段ずつ動かす。♭♮♯ ボタン：変化を直接決める。
- ←→ キー：和音を移る。S／A／T キー：声部を選ぶ。Backspace／Delete：消す。
- 自動送りがオンなら、S→A→T→次の和音のS の順に進む。

## 5. 共通化の候補

**他のアプリでも使えそうなもの**
- **音のデータ形式 `{l,a,o}` と `midi()`、`dia()`、`same()`、`parseNote()`、`nName()`**：異名同音を区別し、全音階の度数も取れる。対位法やフーガでも、音程の度数（5度か減6度か）を正しく判定するのに必要になる。ほかのアプリが MIDI 番号だけで持っているなら、ここが一番食い違いやすい（他アプリの実装は未確認）。
- **調 `makeKey()`、`parseKey()`**：調号と導音を出す。短調を自然短音階として持ち、導音を別に求めるという方針は、アプリ間でそろえる必要がある。
- **2声部の進行の判定**：`P5()`、並行・反行・並達・超越の判定（`check()` の後半）。Gradus（対位法）やフーガ道場でも同じ規則を使う（推測）。いまは `check()` の中に書き込まれているので、関数に切り出す必要がある。
- **規則の登録と結果の形**：`RULES`（id・名前・重さ）と、判定結果 `{rule, sev, cells, where, msg}`。規則の ON／OFF と重さの切り替えを、どのアプリでも同じ画面で扱える。
- **Web Audio の合成音と純正律**：`ac()`、`tone()`、`freqs()`、`JR`。ハモリ道場の純正律の計算とそろえられる（推測。ハモリ道場のコードは未確認）。
- **SVG の大譜表**：`drawStaff()` の譜線、加線、調号の位置（`SH_T`、`FL_T`）、音部記号の拡大。音価がない和音の列に限れば使える。

**共通化しにくいもの**
- **数字付き低音の解釈** `parseFig()`、`ABBR`、`SHAPE`、および「＋4」「＋6」の読み替え：林達也の表記に依存する。コードネームで持つアプリ（リハモ道場、アドリブ道場）とは表し方が違う。ただし「和音 → 構成音・根音・第7音」という出力の形はそろえられる。
- **課題の文字列形式**（`調 バス:数字 …`）：このアプリ専用。
- **画面の状態 `st` と入力の操作**：列の幅 `COLW`、クリックの位置から音を決める処理、自動送り。どれも4声の実施に合わせて作っている。
- **楽譜表示**：音価、小節、符尾、連桁がないので、旋律を扱うアプリの代わりにはならない。VexFlow を使うアプリとは作りが根本から違う。

**アプリ間で食い違いそうな点**（他アプリと突き合わせるときに見る所）
- 音高を音名で持つか MIDI 番号で持つか、オクターヴ番号の基準（ここでは C4＝MIDI 60）
- 短調の扱い（自然・和声・旋律短音階のどれを基準にするか）
- 声部の番号の順番（ここでは 0 がソプラノで上から下へ）
- 楽譜表示に自作 SVG を使うか VexFlow を使うか
- 純正律の基準（ここでは和音ごとに根音を平均律に置く）

## 6. 既知の問題

コードを読んで確かめたもの：
- **同度の連続が「連続8度」と表示される**：`P5()` は同度を `'1度'` として返すが、`check()` は5度以外をすべて「8度」として表示する。
- **同じ和音の転回で第7音が保留されると誤ってエラーになる**：`seventh` は `ch.sig!==ch2.sig` のときに見る。`sig` には数字の形が入るので、7 → 6/5 のように根音が同じでも転回が変われば別の和音として扱われる。
- **導音の規則は主調の導音だけで見る**：副属和音などの一時的な導音は対象外になる。
- **並達は外声（S–B）だけを見る**。音域は上3声だけを見て、バスは見ない。
- **音価、拍子、小節がない**ため、強拍・弱拍に関わる規則（6/4 の置き場所など）は書けない。
- **純正律は和音ごとに根音を平均律に置き直す**。そのため、隣の和音との共通音でも高さが変わることがある。属7の第7音は 9/5、増4度は 36/25 で鳴る。7/4 や 16/9 を選ぶ考え方もあり、検討の余地がある。
- **初回の見本を出したかどうかの印 `ex1init` を `answers` の中に入れている**：課題 id と同じ場所に別の種類の値が混ざっている（604〜608行）。
- **自作課題は1つしか持てない**：読み込み直すと、前の自作課題とその実施が消える。
- **状態がすべて `st` に集まり、描画は毎回 `svg.innerHTML` を作り直す**。部品として切り出すには、状態と描画を分ける必要がある。
- **音部記号の見た目が Noto Music の読み込みに依存する**：読み込めないと端末のフォントに代わり、`fitClefs()` で大きさは合わせるが、形は変わる。

- 教本の章ごとの規則はまだ入っていない（利用者が後で入力する予定。`PLAN.md`）。
